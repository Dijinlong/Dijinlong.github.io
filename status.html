Status pages lie: what to log instead when you resell LLM APIs

Published 2026-11-21 · LONG AI

A green dot means the health endpoint answered. It says nothing about whether the stream was complete, whether the error was typed correctly, or whether the model you asked for is the model that ran. Across 51 upstream sellers, most of the incidents we have handled never turned the dot red.

Failure modes that keep the dot green

  • Silent context truncation: the request succeeds, the answer looks plausible, the tail was dropped.
  • Stream that ends without finish_reason: the client keeps waiting or returns a half sentence.
  • Self-invented error codes: rate limits reported as 500, so retry logic never triggers.
  • Schema drift: an upstream ships a new field name, the adapter keeps working until a specific parameter is used.

What to record per channel

Four numbers per upstream, per minute: request count, error count split by class, p50 and p95 latency, and a completeness flag from the stream validator. The completeness flag is the one that matters — it is the only signal that catches truncation, and it comes from parsing the response, not from the socket closing.

Rank on stability, publish the ranking

Once you score channels, the ranking should drive routing and should be visible. A public board that shows which channels are degraded is useful to customers; a board that only shows "operational" is decoration. We keep the status board and the price table on the same domain so a buyer can see both before signing up.

Alerts should be about behaviour, not existence

Do not alert on "channel down". Alert on "completeness flag below 99% for ten minutes" or "p95 latency doubled against the seven-day baseline". Both fire before customers notice, and both are actionable — you demote the channel and traffic moves, no incident call required.
